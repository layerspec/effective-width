# D1：影像 block bootstrap（敵意審稿 2026-09-15 M3.1／行動表 8；09-20 審稿第 2 條）

**問題**：論文每個承重數字都是單一影像樣本上的點估計。六個配方給了跨權重的散布，
沒有任何東西給跨影像的散布。

**做法**（`code/scripts/bootstrap_images.py`，測試 `tests/test_bootstrap_images.py`）：
- 一次 CPU 前向（6 執行緒、與訓練隊列並行），影像依排序目錄切成 32 個區塊 × 200 張。
  每個區塊、每個站點（conv 輸出 16 個位置／張、池化 1 張 1 樣本、block 輸出）存
  (n, mean, 中心化 scatter)——正是串流累加器合併用的量（Chan 1983）。同時對每個 dense conv
  存「patch 投影到 W 保留奇異方向的均值與變異」，ρ_align 只需要這 r 個變異。
- 重抽：區塊有放回抽 200 次，用「總 scatter 定律」合併成共變異，重算 k*(τ)、erank、PR、
  池化版、ρ_align。rep 0 = 每區塊各一次 = 點估計。
- 門檻照主管線（n/C ≥ 50）：6,400 張下位置估計量 C ≤ 2048 全過，池化估計量只有 C ≤ 128 過。
- 單元測試：全區塊各一次 = 串流共變異；重數 = 複製區塊的 np.cov；對角合併 = 對角。
- 區塊檔（ResNet-50 5.4 GB）在 replicates.csv 寫出後刪除；replicates.csv／align.csv／meta.json 留下。

**為什麼是 block bootstrap**：逐層統計量是整個共變異的泛函，不是逐影像量的平均；逐影像重抽要每張
一個共變異。32 個區塊的 CI 粗但誠實，不假設常態。

## ResNet-50 torchvision V1（2026-09-21，`results/bootstrap/resnet50/`）

先驗證重抽有生效、點估計對得上正式量測：

| 量 | 200 次重抽 |
|---|---|
| 總變異相對 SD | 中位 0.4%，最大 0.9% |
| 有效秩 SD（通道） | 中位 0.09，最大 1.3 |
| k*(0.95) SD（通道） | 中位 0，最大 0.64；53 層中 18 層曾變動 |
| 逐層 k*/C 95% CI 半寬 | 中位 0，最大 0.0078（= C=128 的 1 個通道） |
| rep 0 vs 50k 張正式量測 | k*/C：ρ = 1.000，最大差 0.006；erank/C 最大差 0.009 |

**讀法**：在 n/C ≥ 50 門檻下，影像取樣噪音小於 k* 的整數解析度。M3.1 的答案是「重抽了，
CI 是整數解析度」；審稿人要的 CI 存在，而且窄到只能用通道數報告。

不是影像。這與 M3.1 的擔心正好相反：影像是這個量測裡最不重要的噪音源。
